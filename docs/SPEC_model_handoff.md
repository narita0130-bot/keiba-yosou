## 0. 三行で

- 競馬予想家2人の印を1ヶ月測った結果、**どちらも市場を上回らない**と確定した
- 現行のEVエンジンは**単勝オッズから確率を作っている**ので構造上、市場のコピー
- **オッズを一切使わない確率モデル**を作り、市場に勝てるかを1回だけ検証する

## 1. 前提：何が既に潰れているか

やり直さないこと。全て実データで検証済み。詳細は `docs/handoff.md` §17〜§21。

| 調べたもの | 規模 | 結果 |
|---|---|---|
| 非馬@競馬予想の印 | 372頭 | 複勝83.3%、◎は102頭で**69.1%**（ランダムは80%） |

複勝はSD 140で必要点数が46分の1。**測るときは必ず複勝を使う。**

## 2. 絶対規則（破ると全作業が無意味になる）

### 2-1. 検証期間を見ない

| 期間 | 用途 |
|---|---|
| 2024-01-01 〜 2026-03-31 | 学習・特徴量設計・調整（7,767レース / 107,305行） |
| **2026-04-01 〜 2026-09-20** | **検証。判定の瞬間まで一度も読まない** |

欠損率の確認も、分布の確認も、相関の確認も、**全て学習期間だけ**。
`scripts/data_check.py` は 2026-03-31 で打ち切る実装になっている。同じ作法を守ること。

### 2-2. 使ってはいけない特徴量

- **単勝オッズ (`odds`)、人気 (`ninki`)** ← 使った瞬間に市場のコピーになり、作る意味が消える
- 同一レースの `chaku` `time_sec` `margin` `agari` `passage`（＝結果そのもの）
- **そのレース以降の日付のデータ**。過去集計は必ず `date <` で厳密に切る
  （`<=` にすると当日の結果が漏れる。最頻出の事故）

使ってよいのは、レース前に判明している情報だけ:
`waku` `umaban` `sex` `age` `kinryo` `jockey` `trainer` `weight` `weight_diff`
`distance` `surface` `turn` `weather` `going` `race_class` `field_size` `prize1`、
および**過去走から作った集計**。

### 2-3. 選択肢を並べて一番良いものを選ばない

これが最大の禁止事項。2026-09-19〜20に**同じ罠を3回**確認している。

- Logicの複勝：9月170点で108.1%（+2.0SD）→ 26日1,355点で**93.2%**
- 予想家の一致/食い違い：9月「食い違いが良い」→ 8月で**符号が完全反転**
- 買い方を8通り試す → 「3連複◎◯▲1点」が348.5%と突出（79点の偶然）

**モデルを複数作るなら、学習期間内の交差検証で1つに絞ること。
検証期間に投げるのは1回だけ。** 落ちてもパラメータを変えて再挑戦しない。
再挑戦するなら新しい実データ（2026-10以降）を待つ。

### 2-4. 推測で数値を埋めない

オッズも馬番も、取得できなければ「不明」と書く。これは運用全体の原則。

## 3. 判定基準（`docs/prereg_model.md` 由来。変更禁止）

**2段階、両方を満たさなければ賭けない。**

### 第1関門：市場より正確か（必要条件）

検証期間の各レースで「どの馬が勝つか」の**多クラス対数損失**を比較する。

- モデルの確率
- 市場の確率 = `0.8 / odds` を レース内で正規化したもの

**レース単位で対にした検定で、モデルが有意に低い（p < 0.01）。**
ここで落ちたら第2関門は見ない。対数損失で市場に勝てないなら、
そのモデルには市場が知らない情報が無い。

### 第2関門：実際に黒字か（十分条件）

第1を通った場合のみ、検証期間で**複勝を全点100円**のシミュレーション。

- **合格: 回収率の −1SE > 100%**

複勝払戻は3着以内のみ既知（7頭以下は2着まで）、それ以外は0円として扱う。
Logicの検証と同じ方式（`scripts/marks_stats.py` の `ret()` を参照）。

### 事前の予想（記録済み）

**第1関門で落ちる**と予想している。単勝オッズ由来の市場確率は非常に強い基準。
この予想が外れて両方通ったときだけ賭ける。

### 4-3. 既知の性質（学習期間で確認済み）

- 欠損は `chaku` 0.8%（＝中止・除外・取消の908行と一致）、他は全て0.5%以下
- **89%の馬が2走以上**取れている → 前走ベースの特徴量が作れる
- **馬名の同名衝突は0件**（性別の変化・年齢の逆行なし）→ **馬名をキーにしてよい**
- 走破タイムの異常（12m/s未満）は8行のみ。除外すること
- `passage` は 2026-09 収集分だけ空になることがある（ページ構造の差）

### 4-4. 収集時に踏んだ地雷（再発させないこと）

結果ページには着順表のほかに**指数分析の表**（`IndexMasterCell`）と
**脚質分析の表**（`RunType`）があり、**それらの行も `class="HorseList"` を持つ**。

| | td数 | 先頭セルのクラス |
|---|---|---|
| 本物の着順行 | 15 | `Result_Num` |
| 分析行 | 19〜21 | `Horse_Check Sticky` |

弾かずに集めて**全体の12%（18,149行）が壊れた**。
`scripts/race_data.py` は先頭セルのクラスが厳密に `Result_Num` の行だけを採る。
**データを追加するときは必ず「行数 == field_size」を全レースで検証すること。**

## 5. 作業手順

### 手順1：特徴量を作る（`scripts/build_features.py` を新規作成）

学習期間のみを読み、1行＝1出走で特徴量を出す。**過去集計は `date <` で厳密に切る。**

作るべき特徴量の例（これに限らない。設計は任せる）:

- **馬**: 前走からの日数、前走着順、前走着差、前走上がり3F、前走との距離差・馬場差、
  通算出走数、通算勝率・3着内率、同距離帯実績、同馬場状態実績、同コース実績
- **騎手**: 過去N走の勝率・3着内率（全体／同競馬場／同距離帯）、当該馬との過去コンビ成績
- **厩舎**: 過去の勝率・3着内率
- **当日条件**: 斤量、斤量の前走比、馬体重、馬体重増減、枠、馬番、頭数、
  距離、芝ダ、回り、馬場状態、クラス、賞金
- **相対化**: レース内での偏差（斤量がレース平均から何kg離れているか等）

**注意点**
- 新馬・初出走は過去集計が全て欠損になる。欠損フラグを別列で持つこと
- `margin` は「ハナ」「クビ」「1.3/4」等の文字列。秒差や馬身に変換する関数が要る
- `race_class` は生文字列。クラス（未勝利/1勝/2勝/3勝/オープン/重賞）を抽出する
- 障害（`surface == "障"`）と走破タイム異常8行は除外

出力: `data/features/train.csv`（学習期間のみ）。検証期間は**まだ作らない**。

### 手順2：モデルを学習する

- 目的変数は「そのレースで1着になったか」。レース内で正規化して確率にする
  （条件付きロジット／ソフトマックス、あるいは勾配ブースティングの出力をレース内正規化）
- **学習期間の中で時系列交差検証**して、構成を1つに決める
  （例：2024年で学習→2025年前半で検証、を前倒しでずらす）
- ハイパーパラメータの調整も**学習期間の中だけ**で完結させる

### 手順3：検証を1回だけ実行する（`scripts/eval_model.py` を新規作成）

**ここで初めて検証期間のデータを読む。**

1. 検証期間の特徴量を、学習期間と同じコードで作る（過去集計の参照元には
   学習期間のデータを使ってよい。未来を見なければよい）
2. 第1関門：モデルと市場の対数損失をレース単位で対比較（Wilcoxonの符号順位検定など）
3. 通った場合のみ第2関門：複勝 全点100円の回収率と−1SE
4. **結果は良くても悪くても `docs/prereg_model.md` に追記してコミットする**

### 手順4：結果を記録する

`docs/handoff.md` に §22 として追記。合格でも不合格でも、
**何を試して何が起きたか**を数字で残す。不合格なら「この方向は潰れた」と明記する。

## 8. やりがちな失敗（先回りして潰しておく）

1. **`date <=` で過去集計を切る** → 当日の結果が漏れて対数損失が劇的に改善する。
   良すぎる結果が出たら必ずこれを疑う
2. **オッズを「使っていないつもり」で使う** → 人気順に相関する特徴量
   （例：レース内の馬体重順位ではなく、オッズ由来の何か）を混ぜない
3. **検証期間で欠損率を確認してしまう** → それも「見た」ことになる
4. **モデルを何度も検証期間に投げる** → 1回だけ。2回目からは別の期間が要る
5. **回収率だけ見て対数損失を飛ばす** → 第1関門が必要条件。順序を守る
6. **障害レースを後から除外/追加する** → 事前登録どおり最初から除外
7. **データを追加したあと `行数 == field_size` を検証しない** → §21の12%破損の再発

## 9. この作業の見通し（正直に）

**第1関門で落ちる確率のほうが高い。** JRAの控除率は20〜27.5%で、
単勝オッズ由来の市場確率は数万人の資金が作った強い予測。
レース前情報だけでこれを上回るのは容易ではない。

だが**潰すこと自体に価値がある。** 2026-09-19〜20の1日半で、
「有望に見えた説」を3つ潰した。どれも、乗っていれば金を失っていた。

**負ける方法を確定させ続けることが、長期収支への最大の貢献である。**
不合格という結果を、成果として報告してよい。
