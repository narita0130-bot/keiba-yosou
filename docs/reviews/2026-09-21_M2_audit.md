## 2. 監査役自身の手続き違反（記録する）

**未来漏洩テストのスクリプトで、監査役が検証期間のCSVを開いた。**

削除対象を `data/races/*.csv` 全体から探す実装にしたため、2026-04〜2026-09の
ファイルも読み込んだ。削除行数が23,312と異常に大きいことで気づいた
（2026-03-29の実際の行数は497。差分22,815が検証期間の行数）。

- **見たのは日付ごとの行数のみ。着順・タイム・払戻は一切集計していない**
- 監査役は特徴量設計にもモデル選択にも関与しないため、検証の独立性は損なわれない
- ただし規約違反であることに変わりはない。**以後、監査用スクリプトも
  学習月のファイル名で限定してから開く**

実装側は違反していない。これは監査役の落ち度である。

## 4. 設計として評価できる点

1. **`sys.addaudithook` による能動的な開封拒否。** 事故を「起きてから検出」ではなく
   「起こさせない」設計にしている
2. **正解と出走状態を特徴量CSVと物理的に別ファイルにした。** M3で誤って
   目的変数を入力に混ぜる事故を構造的に防ぐ
3. **「勝者なし」で例外を投げる。** 監査役の不正なテストデータを実際に弾いた
4. **着差を「勝ち馬との秒差」と解釈していない。** 「ハナ」「クビ」等を数値化せず
   カテゴリとして残したのは正しい
5. **補完・標準化をM2で行わず、M3の各学習区間に委ねた。** 全期間で平均を学習すると
   区間をまたいだ漏洩になる

## 5. M3への申し送り（指示ではなく観測事実）

| … | | | |

履歴の蓄積が2024年1月から始まるため、**最初の3〜4ヶ月は検証期間とは別の状態**にある。
検証期間（2026-04〜09）は定常状態（6〜15%）になるはず。

**学習サンプルをどこから採るかはM3の設計判断であり、学習期間の中で決めてよい**
（例：2024年前半を履歴の蓄積専用にして学習サンプルから外す）。
事前登録の期間分割は変更に当たらない。**ただし決めた理由を記録すること。**

## 6. M3で提出するもの

`docs/REVIEW_protocol.md` §2・§4 のとおり。特に、

1. **候補モデルの一覧を、交差検証を実行する前にコミットする。**
   コミット時刻で前後関係を確認する
2. 交差検証が**時系列順**であること（未来で学習して過去を予測しない）
3. 前処理が**各学習区間の中だけ**で学習されていること
4. **最終的に1つに絞れていること。** 複数を検証期間に投げる計画は差し戻す
5. 乱数種、同点時の選択規則、探索範囲を記録すること

**M4の凍結までは検証期間を開かない。開封許可は1回だけ出す。**
