## 1. 指摘への回答（確定。以後変更しない）

### 1-1. 第2関門で買う馬の選び方 → **承認：各レース 予測勝率1位の1頭のみ、複勝100円**

「全出走馬ではモデルの予測と無関係に同じ買い目になる」という指摘は正しい。
それでは検定として成立しない。提案どおり採用し、細目を固定する。

- 同率は**馬番の小さい馬**（決定論的であること）
- 対象は検証期間の**平地**レース（障害は除外）
- **選んだ馬が取消・除外のレースは返還**。投資からも払戻からも除く
- **複勝が発売されない4頭以下は対象外**
- 7頭以下は2着まで。**3着で0円は正しい値**であり例外扱いしない

点数は約1,550点。複勝のSDは140なので SE≒3.6、
**−1SE > 100% は平均103.6%超を要求する。** 妥当な厳しさ。

**補足（提出物に無かった重要事項）**
`data/races/*.csv` に**複勝払戻は入っていない**。判定時に
`fetch_result.race_result()` で検証期間ぶんを取得すること
（`scripts/record_marks.py` と同じ経路）。
**決済専用の事後情報であり特徴量には入れない。取得は判定を実行する時点のみ。
事前に取りに行くと検証期間を開封したことになる。**

### 1-2. 走破タイム異常8行 → **承認：行は残し、過去走の集計からのみ除く**

**指摘が正しく、引き継ぎ書（SPEC §4-3, §5手順1）の「行を除外」が誤り。撤回する。**
当該レースのタイムで出走馬を落とすのは、レース後に判明する情報で出走集合を
変えることになる。

- 当該レースの出走馬・着順は**残す**（予測対象に含める）
- 速度 12m/s 未満 または 20m/s 超 のタイムは**過去走のタイム系集計から外す**
- 外した件数を記録する

8行／107,305行で影響は無視できるが、手続きとして正しいほうを採る。

### 1-3. 第1関門の検定 → **承認：片側Wilcoxon符号順位、α=0.01、平均損失も市場未満**

未定義だった細目を固定する。

| 項目 | 決定 |
|---|---|
| 検定量 | レースごとの「モデルの対数損失 − 市場の対数損失」 |
| 対立仮説 | モデルのほうが小さい（**片側**） |
| 有意水準 | **0.01** |
| 追加条件 | **平均損失もモデル < 市場**（p値だけで通さない） |
| ゼロ差 | **Pratt法**（ゼロを順位付けに含める＝保守的） |
| 1着同着 | 勝者 k 頭に **1/k** の目標質量。**レースは除外しない**（両者同一採点で対称） |
| 単勝オッズ欠損 | 欠けた馬がいるレースは**第1関門から除外**し、**件数を必ず報告** |
| 取消・除外 | モデル・市場とも**その馬を除いた集合**で正規化 |

市場基準は**最終オッズ**から作る。最終オッズは締切直前までの全情報を含むため、
**この比較はモデルに不利な保守的設定**である。それでよい。

## 2. 追加で義務化した事項

提出物の検査案（同日結果の改変で当日の特徴量が不変／オッズ・人気を書き換えても
入力が不変）を**必須**とする。加えて、

> **第1関門でモデルが市場を 0.3 nats 以上下回ったら、合格ではなくバグの兆候として
> 扱い、漏洩監査を行ってから報告すること。**

レース前情報だけで市場をその差で上回ることは通常ありえない。
`date <=` の1文字で当日の結果が漏れ、劇的に良い数字が出るのが最頻出の事故。

## 3. 評価できる点（この方向を維持してほしい）

1. **`data_check.load()` の読み込み境界の修正**。
   旧実装は全月のCSVを開いてから日付で絞っており、要件を構造的に満たしていなかった。
   **ファイルを開く前にファイル名の年月で制限する**という直し方が正しい。
   `open` 呼び出しがゼロであることを単体テストで検査しているのも適切。
2. **馬名は結合キーとし、名前そのものを説明変数にしない**
3. **`race_id` はグループ識別専用**
4. **前走の着差は「前の馬との差」であり「勝ち馬との差」とは限らない**という注意。正確
5. **未定義事項を勝手に決めず、承認を求めて止めた**こと。これが最も重要
