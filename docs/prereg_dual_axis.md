# 事前登録：「両◎軸版」3連複（2026-11-01）

## なぜ登録するか

11/1 天皇賞(秋)で、非馬◎10（2着）とLogic◯17（1着）・▲3（3着）の組み合わせ 3連複3-10-17（42,010円）を、
どの版も取れなかった。「2人の◎をそれぞれ軸に、2人の印の和集合へ流す」形なら23点（トリガミなし）で入っていた。
ユーザーの判断で、この形を今後の版として使う（11/1 ユーザー指示「今後はその形を活かす」）。

**1レースの的中を見てから作った形**なので、11/1 の天皇賞は判定に使わない。

この形は11/1の1レースから作ったので、それより前の記録は「作るときに見ていないデータ」として使える。

テンプレートの3連複より良いが、誤差の範囲内。過去のオッズが無いのでトリガミ除外は再現していない。

## 定義（以後変更しない）

- 対象：非馬の◎がちょうど1頭いて、同じレースに Logic の指名（無料noteの注目馬・厳選・最終結論のいずれか）が1頭以上あるレース。★の有無は問わない（買い目CSVを作ったレース）
- 券種：3連複のみ、各100円
- 軸：非馬の◎、および Logic の◎（印つきの厳選・最終結論があるときだけ。無料noteの注目馬は軸にしない）
- 相手：非馬の印の馬（◎◯▲△☆）と Logic の指名馬の和集合
- 組み方：軸ごとに「軸＋残りから2頭」の全組み合わせ。重複は1点
- トリガミ除外：オッズ（作成時点）が、そのレースのこの版の点数より低い組を外す。残りがすべて満たすまで繰り返す
- 作成：`python3 scripts/build_dual.py --ev data/<日付>.all.ev.json --logic data/<日付>.logic.json [--logic …厳選・最終結論] --out data/<日付>.dual.orders.json`
  → `build_bets_csv.py` で `data/<日付>.dual.bets.csv`／`.dual.autofill.csv`
- 記録：`race_report.py` の `--bets 両◎軸版=data/<日付>.dual.bets.csv`。1日の終わりに `data/dual_tracking.json` へ足す

## 判定

- 測定開始：2026-11-07 以降の開催日（11/1 は含めない）
- 判定時期：対象が **100レース** たまった時点
- 合格条件：回収率の **−1SE が100%を超える**（他の事前登録と同じ基準）
- 3連複は1本の大きな当たりで数字が振れるので、「最大の1本を除いた回収率」も併記する
- 途中で定義をいじらない（いじる場合は別の登録として最初から測り直す）
