# 事前登録：Logic@競馬の過去分による検証

**作成 2026-09-19。過去分のデータを1件も見ていない時点で書いている。**
このファイルはデータ取得の前にコミットする。後から書き換えない。

## なぜ事前に書くか

9/5〜9/19の5日分で、Logicの注目馬は複勝108.1%（170点、+2.0SD）だった。
しかしこの5日は**仮説を見つけた材料そのもの**であり、検証にはならない。同じ5日から
私は既に「非馬が無印の馬は+9.1pt」「7人気以下の食い違いは+4.0SD」といった切り口も
拾っている。切り口を増やせば必ず何か光る。だから**過去分は、結論を先に決めてから見る。**

## 検証に使うデータ（範囲を先に固定する）

- **2026-06-06 〜 2026-09-04 の JRA全開催日 26日分**（`kaisai_days.py` で確定済み）
- Logic@競馬の**無料note**の「競馬場,レース番号,馬名」の行すべて
- 有料の「【厳選】◯Rの予想はコチラ」は対象外（取得できないため）

**この26日のうち、都合で一部だけを取るのは禁止。** 集めたあと
`python3 scripts/kaisai_days.py --from 2026-06-06 --to 2026-09-04 --have "data/*.logic.txt"`
で欠けを確認する。

### 欠けが出た場合の扱い

| 欠けの数 | 扱い |
|---|---|
| 0日 | そのまま検証する |
| 1〜3日 | 理由（未投稿／削除／取得失敗）を記録し、欠けたまま検証。結果に併記する |
| 4日以上で理由不明 | **検証は無効。** 生き残りバイアスを排除できない |

Logicが負けた週のnoteを消していれば、残った記事だけを見た回収率はいくらでも良く見える。
欠けの数と理由は、回収率と同じ大きさで報告する。

## 判定指標（1つだけ。事前に決める）

**Logicの注目馬を全点100円で複勝で買ったときの回収率。**

- 対象は**注目馬の全部**。人気帯・非馬の印の有無・レース種別で絞らない
- 複勝の払戻は結果ページの実額（推定値を使わない）
- 4頭以下で複勝が発売されないレースは除外
- 標準誤差 SE = （1点あたりの払戻のSD）÷ √点数

## 判定ルール（結果を見る前に確定させる）

過去分26日だけで計算した複勝回収率について、

- **合格: −1SE > 100%**
- **不合格: それ以外**

合格なら、Logicの注目馬の複勝を買い目に入れることを検討する。
不合格なら、**9/5〜9/19の108.1%は取り下げる。** 点数を足して再挑戦しない。

## 事前に決めておく、やらないこと

1. **部分集団で判定しない。** 人気帯別・非馬の印の有無・競馬場別・頭数別は
   すべて参考として出すが、**判定には一切使わない。** 過去分で「7人気以下だけ
   +4SD」が出ても、それは判定を動かさない
2. **指標を後から変えない。** 複勝が不合格で単勝が合格でも、合格にしない
3. **期間を後から延ばさない。** 26日で不合格なら、5月分を足して再計算しない
4. **日を除外しない。** 特定の日が極端でも外さない
5. **9/5〜9/19と合算した数字は参考として出すが、判定には使わない**

## 想定される結果（これも先に書いておく）

私の予想は**不合格**。理由は、5日分の+2.0SDは今日だけで4通りの切り口を試した
末に出たもので、多重比較を考えると見かけほど強くないため。

**この予想が外れて合格したとき、初めて意味のある発見になる。**

## 実行手順

```bash

# 2. 欠けを確認（これを先にやる）
python3 scripts/kaisai_days.py --from 2026-06-06 --to 2026-09-04 --have "data/*.logic.txt"
# 3. 馬番を解決（確定済みレースは結果ページ1枚で済む／取りこぼしは流し直せば埋まる）

# 4. 記録に追加
python3 scripts/record_marks.py --logic data/<日付>.logic.json
# 5. 集計
python3 scripts/marks_stats.py
```

## 修正1（2026-09-19、集計を一度も実行していない時点）

### 何が起きたか

6/6〜7/26の16日は全部揃った（欠け0）。8月分は **8/1・8/2の2日を取得した時点で
noteの無料閲覧上限に達し**、8/8・8/9・8/15・8/16・8/22・8/23・8/29・8/30 の
**8日が取得できなくなった**。

### この欠けは生き残りバイアスか → No

当初の規定「4日以上で理由不明なら無効」の趣旨は、**Logicが負けた週の記事を消して
いる可能性**を排除することだった。今回の欠けはそれに当たらない。

- 記事は存在している。読めないのは**閲覧回数の上限**という読み手側の制約
- どの8日が欠けるかは**日付順に読み進めた結果**であり、レース結果とは無関係に決まった
- 欠けた8日について、我々は成績を一切知らない（良かったから外した／悪かったから
  外した、のどちらでもない）

したがって**結果と独立な欠測**として扱い、検証は続行する。

### 検証範囲を確定させる（ここで凍結する）

**2026-06-06 〜 2026-08-02 の18日。** 内訳は6月8日・7月8日・8月2日。

| 8/8〜8/30の8日 | **この検証には二度と加えない** |
|---|---|

**結果を見たあとにこの8日を足して再計算することは禁止する。** 不合格だったときに
点数を足して覆すのは、事前登録を無意味にする典型的なやり方である。後日入手できても、
それは今後の前向きな記録に入れるだけで、この判定には使わない。

18日で点数は十分足りる見込み（6-7月は3場開催で1日50〜63頭、必要な約510点を超える）。
足りなければ「点数不足で判定不能」と報告する。それも結果のひとつとして受け入れる。

### 変えないもの

判定指標（注目馬の全部・複勝・全点100円）と判定ルール（−1SE > 100%）は変更しない。
「やらないこと」の5項目も変更しない。

## 修正2（2026-09-19、集計はまだ一度も実行していない）

修正1で「8/8〜8/30の8日は二度と加えない」と書いたが、**本人が明日もう一度
閲覧を試すとのことなので、条件付きで加えられるようにする。**

### なぜ緩めてよいか

凍結の趣旨は「**結果を見たあとに**点数を足して判定を覆すこと」の禁止であって、
「データを増やすこと」の禁止ではない。集計を一度も実行していない段階でデータが
増えるのは、検証の質が上がるだけで何も損なわれない。

### 加えてよい条件（両方を満たすときだけ）

1. **集計を一度も実行していない時点で届くこと**
2. 追加するのは**その時点で入手できた全部**であること（日を選ばない）

### 絶対に変えない一線

**一度でも集計を実行して回収率を見たあとは、いかなるデータも追加しない。**
そのあとに8日が入手できても、今後の前向きな記録に入れるだけ。

### 実際の進め方

- 明日、入手できた分をすべて取り込む
- **本人が「これ以上は取れない」と言った時点で範囲を確定**し、そこで初めて集計する
- 私の側から「もう集計しよう」とは言わない。範囲の確定は本人が宣言する
- 確定時点で18日なら18日、26日なら26日で判定する

### 変えないもの

判定指標（注目馬の全部・複勝・全点100円）と判定ルール（−1SE > 100%）、
「やらないこと」5項目、私の事前予想（不合格）は変更しない。

## 結果（2026-09-19、集計は1回だけ実行した）

### 判定：**不合格**

| | |
|---|---|
| 検証範囲 | 2026-06-06 〜 2026-09-04 の**26開催日、欠け0** |
| 対象 | Logicの注目馬の**全部**（704レース中の該当分） |
| 買い方 | 複勝 全点100円 |
| 点数 | **1,355点**（投資 135,500円） |
| 払戻 | 126,270円 |
| 収支 | **−9,230円** |
| 的中 | 558/1,355（41.2%） |
| **回収率** | **93.2%** |
| 標準誤差 | ±4.7 |
| ±1SE区間 | 88.4% 〜 97.9% |
| **−1SE** | **88.4%** → 100%を下回る → **不合格** |

事前に書いた予想（不合格）どおりだった。

### 9/5〜9/19の108.1%は取り下げる

事前登録のとおり、**取り下げる。点数を足して再挑戦しない。**

| | 点数 | 回収率 | ±1SE |
|---|---|---|---|
| 9/5〜9/19（仮説の元） | 170 | 108.1% | 94.2〜122.0% |
| **6/6〜9/4（検証）** | **1,355** | **93.2%** | **88.4〜97.9%** |
| 31日すべて合算（参考） | 1,525 | 94.8% | 90.3〜99.3% |

170点の108.1%は、1,355点で測り直すと93.2%だった。**区間が重なっていないわけではないが、
8倍の点数で測った93.2%のほうが信頼できる。** 5日分の+2.0SDは、その5日を選んで
見たことによる見かけの上振れだったと判断する。

### 参考（判定には使っていない）

- 同じ26日を単勝で: 1,355点 回収率85.8%（±8.7）的中16.7%
- 月別（複勝）: 6月 404点 111.3% ／ 7月 465点 83.1% ／ 8月 486点 87.9%

**6月だけ見れば111.3%で、9月の108.1%と同じ話ができてしまう。** 月を選べば
100%超の月は必ず見つかる。これが「部分集団で判定しない」と事前に決めた理由。

### 注意：ランダム比 +2.8SD について

93.2%は、ランダムに買ったときの80%に対して **+2.8SD** ではある。
**しかしこれは「勝てる」を意味しない。** 控除率20%を取り返せていない以上、
買い続ければ確実に減る。「ランダムよりマシ」と「プラス」の間には20ptの差がある。

### 結論として確定したこと

1. **Logicの注目馬は、そのまま買っても負ける。** 複勝で93.2%、単勝で85.8%
2. 9/5〜9/19の好成績は再現しなかった
3. **買い目には入れない。** 今後も記録は続けるが、採用条件（−1SE > 100%）を
   満たさないかぎり変更しない
