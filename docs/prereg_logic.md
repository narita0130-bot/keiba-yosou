# 事前登録：Logic@競馬の過去分による検証

**作成 2026-09-19。過去分のデータを1件も見ていない時点で書いている。**
このファイルはデータ取得の前にコミットする。後から書き換えない。

## なぜ事前に書くか

9/5〜9/19の5日分で、Logicの注目馬は複勝108.1%（170点、+2.0SD）だった。
しかしこの5日は**仮説を見つけた材料そのもの**であり、検証にはならない。同じ5日から
私は既に「非馬が無印の馬は+9.1pt」「7人気以下の食い違いは+4.0SD」といった切り口も
拾っている。切り口を増やせば必ず何か光る。だから**過去分は、結論を先に決めてから見る。**

## 検証に使うデータ（範囲を先に固定する）

- **2026-06-06 〜 2026-09-04 の JRA全開催日 26日分**（`kaisai_days.py` で確定済み）
- Logic@競馬の**無料note**の「競馬場,レース番号,馬名」の行すべて
- 有料の「【厳選】◯Rの予想はコチラ」は対象外（取得できないため）

**この26日のうち、都合で一部だけを取るのは禁止。** 集めたあと
`python3 scripts/kaisai_days.py --from 2026-06-06 --to 2026-09-04 --have "data/*.logic.txt"`
で欠けを確認する。

### 欠けが出た場合の扱い

| 欠けの数 | 扱い |
|---|---|
| 0日 | そのまま検証する |
| 1〜3日 | 理由（未投稿／削除／取得失敗）を記録し、欠けたまま検証。結果に併記する |
| 4日以上で理由不明 | **検証は無効。** 生き残りバイアスを排除できない |

Logicが負けた週のnoteを消していれば、残った記事だけを見た回収率はいくらでも良く見える。
欠けの数と理由は、回収率と同じ大きさで報告する。

## 判定指標（1つだけ。事前に決める）

**Logicの注目馬を全点100円で複勝で買ったときの回収率。**

- 対象は**注目馬の全部**。人気帯・非馬の印の有無・レース種別で絞らない
- 複勝の払戻は結果ページの実額（推定値を使わない）
- 4頭以下で複勝が発売されないレースは除外
- 標準誤差 SE = （1点あたりの払戻のSD）÷ √点数

## 判定ルール（結果を見る前に確定させる）

過去分26日だけで計算した複勝回収率について、

- **合格: −1SE > 100%**
- **不合格: それ以外**

合格なら、Logicの注目馬の複勝を買い目に入れることを検討する。
不合格なら、**9/5〜9/19の108.1%は取り下げる。** 点数を足して再挑戦しない。

## 事前に決めておく、やらないこと

1. **部分集団で判定しない。** 人気帯別・非馬の印の有無・競馬場別・頭数別は
   すべて参考として出すが、**判定には一切使わない。** 過去分で「7人気以下だけ
   +4SD」が出ても、それは判定を動かさない
2. **指標を後から変えない。** 複勝が不合格で単勝が合格でも、合格にしない
3. **期間を後から延ばさない。** 26日で不合格なら、5月分を足して再計算しない
4. **日を除外しない。** 特定の日が極端でも外さない
5. **9/5〜9/19と合算した数字は参考として出すが、判定には使わない**

## 想定される結果（これも先に書いておく）

私の予想は**不合格**。理由は、5日分の+2.0SDは今日だけで4通りの切り口を試した
末に出たもので、多重比較を考えると見かけほど強くないため。

**この予想が外れて合格したとき、初めて意味のある発見になる。**

## 実行手順

```bash
# 1. 各日の note 本文を data/<日付>.logic.txt に置く
# 2. 欠けを確認（これを先にやる）
python3 scripts/kaisai_days.py --from 2026-06-06 --to 2026-09-04 --have "data/*.logic.txt"
# 3. 馬番を解決（確定済みレースは結果ページ1枚で済む／取りこぼしは流し直せば埋まる）
python3 scripts/parse_logic.py --text data/<日付>.logic.txt --out data/<日付>.logic.json
# 4. 記録に追加
python3 scripts/record_marks.py --logic data/<日付>.logic.json
# 5. 集計
python3 scripts/marks_stats.py
```
